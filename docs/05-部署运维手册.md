# VSaaS 部署运维手册

---

## 1. 环境要求

| 组件 | 最低建议 |
|------|----------|
| OS | Linux x86_64 |
| JDK | 17+ |
| Node | 18+（构建前端） |
| CPU/内存 | 演示 4C8G；生产按路数评估 |
| 端口 | 5432, 6379, 8848, 9000, 1935, 8080, 8001-8008, 3000, 9080 |

---

## 2. 快速启动（演示）

```bash
# 1. 中间件
cd docker && docker compose up -d

# 2. 初始化库
psql -h 127.0.0.1 -U vsaas -d vsaas -f ../sql/01-schema-core.sql
psql -h 127.0.0.1 -U vsaas -d vsaas -f ../sql/02-schema-billing-rbac.sql
psql -h 127.0.0.1 -U vsaas -d vsaas -f ../sql/seed-demo.sql

# 3. 后端
cd .. && mvn clean install -DskipTests
# 分别启动 vsaas-auth ... vsaas-user

# 4. 前端
cd frontend && npm install && npm run dev
```

访问：http://localhost:3000  
默认用户以库内 seed 为准，**生产必须改密码**。

---

## 3. 生产配置

1. 复制 `docker/prod/env.production.example` → `.env`  
2. 必改：`DB_PASSWORD`、`VSAAS_JWT_SECRET`、`VSAAS_HOOK_SECRET`、`VSAAS_PLAY_SECRET`、MinIO 密钥  
3. 开启：`VSAAS_HOOK_AUTH_ENABLED=true`  
4. 中间件：`docker compose -f docker-compose.prod.yml up -d`  
5. 业务：镜像构建后 K8s 部署，参考 `k8s/`  

### 3.1 健康检查

```bash
curl http://127.0.0.1:8001/actuator/health
```

各服务均暴露 `health`（部分模块已加 actuator）。

### 3.2 定时任务

多副本必须保证库表 `shedlock` 存在，避免重复出账/清理。

---

## 4. 流媒体

- 推流：`rtmp://<srs-host>/live/{tenantId}_{channelId}`  
- 预览：调用 media 接口获取带 token 的 FLV/HLS  
- Hook：`docker/srs/srs.conf` 中 `on_dvr` 指向 record 服务  
- 若 SRS 无法加自定义 Header，用反向代理注入 `X-Hook-Secret`

## 5. 备份与恢复

| 数据 | 建议 |
|------|------|
| PostgreSQL | 每日逻辑备份 + 定期恢复演练 |

## 6. 日常运维检查

- [ ] 服务 health 是否绿  
- [ ] 设备在线率与心跳延迟  
- [ ] SRS 带宽与录制磁盘  
- [ ] 未支付账单与欠费租户  
- [ ] 证书与密钥轮换计划  

---

## 7. 常见问题

| 现象 | 处理 |
|------|------|
| 登录失败 | 查用户状态与密码哈希；确认无演示兜底依赖 |
| 预览无画面 | 确认已推流且 streamKey 一致；查 SRS |
| Hook 401 | 检查 X-Hook-Secret 与 auth-enabled |
| 无法新增设备 | 查配额与欠费状态 |
| 出账重复 | 查 ShedLock 与账单唯一约束 |

更细联调步骤见根目录 `CLOSED_LOOP.md`。
